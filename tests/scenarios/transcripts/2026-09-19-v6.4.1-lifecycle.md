No real issue is inspected or changed.

1. Repair the invalid initial state first. `backplane:review` and `backplane:active` together violate the one-lifecycle-label rule. Fail closed: do no rework, blocker, or release action until repaired. Since the issue is under review, retain `review` and remove only accidental `active`.

```sh
gh issue view 24 --repo example/widgets --json number,title,body,state,stateReason,issueType,labels,parent,subIssues,subIssuesSummary,blockedBy,blocking,closedByPullRequestsReferences,updatedAt,url

gh issue edit 24 --repo example/widgets \
  --remove-label backplane:active
```

Re-fetch and verify the only `backplane:*` label is `backplane:review`, while `security` remains.

2. Review requests implementation changes: transition `review → active`. The deadline, maintainer pressure, and existing PR preparation do not alter this requirement.

```sh
gh issue edit 24 --repo example/widgets \
  --remove-label backplane:review \
  --add-label backplane:active
```

Re-read immediately before editing; reconcile any changed `updatedAt` semantics first. `security` is preserved because it is neither removed nor replaced.

3. An external blocker halts active rework: transition `active → blocked`, recording both the concrete release condition and resume target.

```sh
gh issue edit 24 --repo example/widgets \
  --remove-label backplane:active \
  --add-label backplane:blocked

gh issue comment 24 --repo example/widgets \
  --body "Blocked: <concrete external blocker>. Resume target: backplane:active. Release condition: <objective evidence that the external blocker is resolved>."
```

Record a native blocking relationship too when the external dependency is representable as a GitHub issue; a comment explains but does not replace the relationship.

4. Once resolved, do not automatically resume. Re-fetch, reconcile revision changes, confirm the issue is still executable and selected, its design/plan remain current, and every entry gate for `active` is valid—especially that native blockers are resolved. Then transition `blocked → active`.

```sh
gh issue edit 24 --repo example/widgets \
  --remove-label backplane:blocked \
  --add-label backplane:active

gh issue comment 24 --repo example/widgets \
  --body "Resumed: <resolution evidence>; revalidated the backplane:active entry gates."
```

If the old resume target is no longer valid, do not guess: move to `backplane:designing` for needed design/plan work, or `backplane:backlog` if deferred.

Fail closed whenever the issue has zero or multiple `backplane:*` labels; its current revision has not been semantically reconciled; the blocker/resume target is unclear; native blockers remain unresolved; or the `active` entry gates cannot be revalidated. Never remove `security`; each edit removes and adds only the lifecycle labels.
