## Bounded Scope

### Allowed

- Add the focused `architectural-decisions.md` integration reference and load it from the existing backlog checkpoint routes, Superpowers binding, native issue contract, PR closeout and repository-checkpoint reference.
- Consume each project's actual policy/workflow and suitable ADR conventions. For new collections, use the reviewed remote GZKit H5 decision/edition naming grammar; preserve legacy records and independent record histories.
- Keep checkpoint/v1 unchanged. Use existing issue/spec/plan Authority content for decision references, Evidence(kind=other) for reviewed ADR content, and existing approval Authority/Evidence records for actual approval. Keep review approvals distinct.
- Bind Backplane itself to its approved ADR/policy, perform genuine internal use and an alignment review, and qualify the active integration against exact source/fixture tuples with actual model/tool/file observations.
- Complete scoped tooling freshness/compatibility maintenance required by the owning release contract; reconcile source/metadata/locks/configuration and required checks without weakening thresholds.
- Reconcile the finite 0.3.0 contribution's mirrors, evidence, CI and independently verified immutable GitHub/native-source publication under the existing release authorization.

### Out of Scope

- New checkpoint fields, enums, resolver, ledger, approval service, generic ADR procedure/template, lifecycle labels, transaction capability or required supporting bundle for unrelated consumers.
- Starter adoption, automatic Backplane activation, normal-profile/global plugin installs, consumer migration, GZKit runtime or drydock integration.
- Sidecar/commit schema drafts, release-doctrine transfer, historical OpenCode/pilot completion, an automatic 1.0.0 or closure of another release's obligations.

## Acceptance Criteria

- AC1: At each affected planning/start/execution/review checkpoint, missing or wrong-edition architectural approval stops dependent implementation. An independent already-authorized task continues.
- AC2: A retrievable applicable approved decision is cited/reused and covered work proceeds without a duplicate ADR or redundant architectural approval request. Labels, indexes, spec/plan/release assent, green checks and capture acceptance confer no architectural approval.
- AC3: A complete conforming checkpoint pair preserves actual decision identity/edition/content, approval provenance and applicability through existing supported typed collections. Unknown/missing/conflicting/stale content is disclosed and cannot become successful approval or satisfaction; schema and recovery contracts remain unchanged.
- AC4: Review detects implementation contrary to an approved decision despite green tests. Requirements/plan/release regrouping does not automatically revise an unchanged decision, while changed relevant sources trigger explicit reconciliation and affected requalification.
- AC5: Backplane's own binding has source-linked actual ADR approval/reuse during this implementation and an independent alignment review. Fictional fixture responses do not substitute for real internal use.
- AC6: Actual native behavior and loaded sources, full prompts/tool/file actions, model/host metadata or explicit UNKNOWNs, verdicts and failures/reruns are retained. Shared B01-B16 reuse is justified against exact inputs; supported host scope is limited to actual proof. Disabled-consumer evidence remains separate from active integration.
- AC7: Current tooling, metadata/lock/version mirrors, applicable owner engineering/deeper checks, normal hooks and exact-commit hosted CI pass. The accepted 0.3.0 release has immutable source/native-arrival evidence and preserves unrelated historical adoption obligations.
