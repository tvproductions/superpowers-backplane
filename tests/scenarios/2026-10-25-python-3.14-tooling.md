# Backplane tooling environment: Python 3.14

The operator explicitly requested that this repository's tooling environment use
Python 3.14 consistently with the companion starter. This is a project-local
decision, not formal starter adoption or a consuming-project runtime requirement.

Before the change there was no root `.venv`, `pyproject.toml`, `uv.lock` or
`.python-version`; the #19 harness used uv-managed 3.13.14 directly. uv 0.13.5
reported 3.14.9 available, and gh confirmed official CPython `v3.14.9` among
`python/cpython` tags. The current starter main also names 3.14.9, but the runtime
selection was independently confirmed rather than inferred from that document.

`uv venv --managed-python --python 3.14.9 .venv` downloaded the managed interpreter
and created the local environment. `uv python pin 3.14.9` wrote `.python-version`.
AGENTS records the 3.14 family and portable creation/execution commands;
`.gitignore` excludes `.venv/`. Observed `sys.executable` resolves to this root's
`.venv/Scripts/python.exe`, `sys.prefix` is this `.venv`, and `sys.base_prefix`
is uv's managed `cpython-3.14.9-windows-x86_64-none` installation. `pyvenv.cfg`
reports `version_info=3.14.9`, uv 0.13.5 and no system site packages.

The exact previously used Ruff 0.12.11 and ty 0.0.69 were installed locally through
`uv pip install --python .venv ruff==0.12.11 ty==0.0.69`; this scoped interpreter
change did not evaluate or claim latest-tool freshness. A future tooling-freshness
review should reconcile these retained versions with current starter guidance.
The repository has no shipped Python package or adopted starter profile, so this
change does not introduce packaging metadata, a product version, bundle or lock.
